# 供应商质量报告智能审核工具

当前版本：`v0.5.3`。详细修改原因和版本记录见 [CHANGELOG.md](CHANGELOG.md)。

把供应商提供的质量证明书、检测报告或合格证上传进去，程序会自动识别供应商、提取内容、对照审核依据、列出问题，并生成可以下载的 Excel 问题清单和带红框原页证据的 PDF 审核报告。

所有报告和审核数据默认保存在自己的电脑上。

## 一、准备工作

只需要提前安装：

- [Python 3.11 或更高版本](https://www.python.org/downloads/)
- 可选：自己的 LLM 和 OCR 服务

安装 Python 时，Windows 用户记得勾选 `Add Python to PATH`。

> 程序不会自动下载大型 AI 模型。没有配置 LLM 时，数值、单位和一致性等本地规则仍然可以运行；扫描件和图片需要 OCR 服务。

## 二、启动软件

### Windows

1. 下载并解压整个项目。
2. 双击 `start.bat`。
3. 第一次启动会自动安装依赖，时间稍长。
4. 浏览器会自动打开 `http://127.0.0.1:8501`。

停止软件：双击 `stop.bat`。

### macOS

1. 下载并解压整个项目。
2. 双击 `start_macos.command`。
3. 第一次启动会自动安装依赖并打开浏览器。
4. 保持 Terminal 窗口开启；按 `Control-C` 停止软件。

如果 macOS 提示没有执行权限，在 Terminal 中进入项目目录，执行一次：

```bash
chmod +x start_macos.command
```

## 三、第一次配置 AI 服务

打开顶部的“系统设置”，分别填写：

1. `LLM`：填写 OpenAI-compatible 或 Ollama/LM Studio 地址、模型名称和 API Key。
2. `OCR`：填写 MinerU-compatible 服务地址、Backend 和语言。

LLM 模型名称建议按 `/v1/models` 返回的 ID 明确填写；也可以留空，程序会自动读取模型列表并使用第一个可用模型。审核任务建议温度设为 0，并发数保持默认 1，单条任务超时保持 300 秒。LM Studio 单模型只有在服务端明确支持并行推理时才建议提高并发。

程序不再需要 Embedding/向量模型。审核依据使用本地关键词、条款号和已确认的结构化要求检索。

常见的本机地址示例：

```text
http://127.0.0.1:1234
http://127.0.0.1:11434
```

只填端口地址即可，程序会自动补全 `/v1`。

配置完成后：

1. 点击“保存配置”。
2. 点击“一键测试全部服务”。
3. 确认 LLM 和 OCR 的测试结果。

如果使用公网接口，需要先开启“允许公网服务”。开启后，文档内容可能发送到该外部服务。

## 四、导入审核依据

1. 打开“审核依据库”。
2. 选择类别：采购/技术要求、图纸、企业标准或标准规范。
3. 上传 PDF、DOCX、XLSX 或 TXT。
4. 点击“解析并加入依据库”。

审核依据只需导入一次，以后可以重复选择使用。

## 五、开始审核

1. 打开“开始审核”。
2. 选择审核模板。
3. 选择审核方式：
   - `自适应审核`（推荐）：每条启用规则只调用一次模型，使用紧凑 JSON 并关闭展开思考。证据无法逐字定位时转为人工复核，不重复调用模型，也不生成虚假红框。
   - `思考模式深度复核`：每一条规则都完整思考，耗时和上下文占用更高。
4. 选择本次使用的审核依据。
5. 左侧上传供应商质量文件。
6. 如有临时采购要求或图纸，在右侧上传补充依据。
7. 点击“开始审核”。

页面会显示当前正在做什么，以及调用的是 OCR、LLM 还是本地规则。长时间没有新进度时，也会显示等待提示。

### 规则模板怎样调用 LLM

规则模板中的“必检项目”采用一行一任务：

1. 本地解析、OCR、确定性数值规则先执行。
2. 系统读取模板的全部必检项目。
3. 每一行单独组装相关原页证据，并按“系统设置”的并发数同时调用 LLM。
4. 每条任务分别保存“合格 / 不合格 / 存疑 / 不适用 / 调用失败”、证据、页码、判断逻辑和置信度。
5. 全部任务结束后，系统把不合格与存疑项合并到问题清单，并保留所有合格项作为完整审核记录。

例如模板有 12 行必检项目，自适应模式就会执行 12 次相互独立的 LLM 判断。某一条超时时只把该条标为“调用失败”；若模型发现疑点但证据无法逐字定位，则降为“存疑/待人工复核”，不会伪造证据，也不会重复调用模型。在模板中新增一行即可增加新规则，不需要修改代码。

“专家审核说明”是所有任务共享的判断边界，不会按行产生额外调用。LLM 的不合格结论必须引用原文件中的逐字证据；字段完全缺失时必须说明检查过的文件和页面。无法验证的模型疑点只会进入人工复核，不会作为确定的不合格结论或生成红框截图。

> 自适应模式和深度模式的调用次数都与启用的必检项目行数一致，每条规则只调用一次。区别是自适应模式关闭展开思考并限制为紧凑输出，深度模式为每条规则启用完整思考。页面会显示并发数、已完成条数和刚完成的任务。

规则模板页面使用一行一项的表格：可直接新增行、修改文字、单独启停，也可勾选或全选后批量删除。上传后，本次使用的必检项和专家说明会保存为批次快照；之后修改模板不会改变已经提交的审核事件。

审核紧固件质量文件时，选择内置的“通用紧固件质量文件审核”模板。程序会按页检查扫描内容，保留 PDF 表格行关系，核对 `Sample/Pass`、标准值/实测值、WDC、COC 与 COI/MTR 完整性。LLM 只允许补充带原文件名、页码和原文证据的问题，无法在原页验证的结论会被丢弃。

## 六、查看结果

打开“审核中心”，可以：

- 在“全部任务 Dashboard”查看所有 SQLite 队列任务、排队/运行/完成数量和本地 worker 是否在线。
- 点击任一任务，查看当前阶段、进度、调用资源、尝试次数、失败原因并定位到对应批次。
- 点击 Dashboard 总数卡片，立即筛选全部批次、已完成、审核中、有问题、严重问题或待复核批次。
- 点击批次表格行，直接查看该批次的问题、文件、处理过程和导出。
- 查看问题等级和审核结论。
- 查看每一条模板规则的独立结论；点击规则行可展开证据、文件、页码和失败原因。
- 对照供应商原文与审核依据条款。
- 确认、驳回、整改或关闭问题。
- 按页查看报告文字。
- 预览图片和 PDF 页面。
- 查看 OCR、解析和本地关键词检索信息。
- 下载原始报告。
- 下载 Excel 问题清单和带证据截图的 PDF 审核报告；两种导出均包含逐条规则汇总。
- 停止正在运行的审核，或将审核记录移入30天回收站。

紧固件模板会直接执行经过样例报告验证的文件完整性、Sample/Pass、标准/实测值和数据缺失检查；字段完全缺失时展示检查范围，不会伪造红框。

## 七、常见问题

### 双击启动后没有反应

确认已经安装 Python 3.11+。Windows 用户还要确认安装时勾选了 `Add Python to PATH`。

### 提示 LLM 连接失败

先在“系统设置”填写 LLM Base URL（例如 `http://127.0.0.1:1234/v1`）。模型名称留空时，程序会读取 `/v1/models` 并使用第一个模型；若指定模型，名称必须与该接口返回的 ID 一致。

### 图片或扫描 PDF 无法审核

图片和扫描件没有文字层，需要先配置可用的 MinerU-compatible OCR 服务。

混合型 PDF（部分页面有文字、部分页面是扫描图）也会逐页检查。OCR 未连接时，空白扫描页会明确显示为“需人工复核”，不会被静默忽略。

### 审核一直停在 LLM

页面会显示正在调用的模型和地址。首次加载本地模型可能较慢；如果等待提示持续增长，请检查模型服务是否仍在运行。

### 一直显示“SQLite 本地任务队列”

打开“审核中心”最上方的“全部任务 Dashboard”：

- `本地 worker = 在线`：任务通常会在数秒内被领取；等待超过15秒时页面会显示队列异常警告。
- `正在恢复`：worker 曾退出，启动器正在自动重启。
- `异常/失联`：查看项目目录下的 `logs/worker.log`，里面会保留后台进程的真实错误。

新版启动器会先初始化数据库，再分别启动网页和 worker；worker 意外退出时会自动恢复，不会让网页正常但任务永久排队。

## 数据安全

- 数据库、上传文件、本地检索数据和日志默认保存在项目的 `data/` 与 `logs/` 目录。
- API Key 加密保存在本地，页面只显示掩码。
- Git 配置已经排除数据库、报告、索引、日志、密钥和虚拟环境，避免误上传业务资料。
